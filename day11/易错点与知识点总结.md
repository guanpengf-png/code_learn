## 一、最高频的 6 类错误

### 1. 空指针 / 野指针

| 现象 | 常见写法 | 正确做法 |
|---|---|---|
| `EXC_BAD_ACCESS (address=0x0)` | `malloc` 后立刻 `p = NULL` | 保留 malloc 的返回值 |
| 崩溃在第一个解引用处 | `Stack *s; init_stack(&s, 5);` | `Stack s; init_stack(&s, 5);` |
| 类型不匹配 warning | 函数参数是 `Stack *`，传 `&s`（`Stack **`） | 传 `&s` 时函数参数应为 `Stack *`，而 `s` 是结构体变量 |
| 明明长度够却拿到 NULL | `if (list->length > index) return NULL;`（写反） | `if (index <= 0 || index > list->length) return NULL;` |

**记住**：`address=0x0` 几乎总是空指针，不是数组越界。先找"哪里把指针设成了 NULL / 哪里根本没 malloc"。

### 2. 边界差一位

见 [第二节](#二边界检查速查表)。这一类错误占全部 bug 的一半以上。

### 3. 状态不同步

- `realloc` 成功但忘了更新 `capacity`
- 删除元素/节点后忘了 `length--` / `edge_count--`
- 初始化时**先用成员、后赋值**：
  ```c
  // 错：vert_number 还是随机值
  g->arcs = malloc(sizeof(int*) * g->vert_number);
  g->vert_number = n;
  // 对：先赋值
  g->vert_number = n;
  g->arcs = malloc(sizeof(int*) * g->vert_number);
  ```

### 4. 内存所有权混乱

| 错误 | 后果 |
|---|---|
| `free(q->data)`，但 `data` 是 `int data[MAX]` 内嵌数组 | 释放非堆指针 → abort |
| 只 `free(list->header)`，不遍历 | 泄漏其余节点 |
| `free(p)` 后继续使用 `p` | use-after-free，结果随机/崩溃 |
| 对同一块内存 `free` 两次 | double free → abort |
| 二级指针只分配第一层 | 解引用垃圾指针 → 段错误 |
| `free` 后不置 NULL，重复调用 destroy | 二次释放 |

**判断标准**：这个指针是 `malloc/calloc/realloc` 出来的吗？是才 `free`。
**释放顺序**：先内层（行/节点），再外层（指针数组/头指针），最后结构体本身。

### 5. 指针类型不匹配

编译器给出的这三条 warning，几乎 100% 是真 bug：

```
incompatible pointer types passing 'Graph *' to parameter of type 'Queue *'
incompatible pointer to integer conversion returning 'int *' from a function with result type 'int'
incompatible pointer types passing 'int[5][5]' to parameter of type 'int *'
```

不要因为"只是 warning"跳过。

### 6. 未定义行为（UB）

| UB | 例子 | 后果 |
|---|---|---|
| 有符号整数溢出 | `*a = *a + *b` 交换 | `-O2` 下可能被优化成空操作 |
| 数组越界写 | `push` 判断成 `length > capacity` | 破坏堆，可能不立刻崩 |
| 未初始化变量参与运算 | 用未赋值的 `size_t` 算 `malloc` 大小 | 分配大小随机 |
| 中间值溢出 | `(lo + hi) / 2` | 大数组下 `mid` 变负数 |
| 解引用已释放内存 | `free(g); graph_bfs(g, ...)` | 崩溃或数据错乱 |

## 二、边界检查速查表

| 操作 | 合法条件 | 非法判断 | 常见错误 |
|---|---|---|---|
| 按下标插入 | `0 <= pos <= length` | `pos > length` | — |
| 按下标删除/访问 | `0 <= pos < length` | `pos >= length` | 写成 `pos > length` |
| 顺序表删除移位 | `i < length - 1` | — | 写成 `i < length`，读 `data[length]` |
| push（顺序栈） | `length < capacity` | 扩容条件 `length == capacity` | 写成 `length > capacity`，越界写 |
| pop / 删除 | `length > 0` | `length == 0` 时失败 | 空表时 `length - 1` 下溢成 `SIZE_MAX` |
| 链表插入 | `0 <= index <= length` | `index > length` | — |
| 链表删除 | `0 <= index < length` | `index >= length` | 判断写反 |
| 链表取前驱 | `0 < index <= length` | `index <= 0 \|\| index > length` | 写成 `length > index` |
| 图加/删/查边 | `0 <= v < vertex_count` | `v >= vertex_count` | 写成 `>` |
| 循环队列判满 | — | `(rear+1) % capacity == front` | 实际可用容量 = capacity - 1 |

### 每写一个操作，问 4 个问题

1. **空的时候**会怎样？（`length == 0`）
2. **满的时候**会怎样？（`length == capacity`，多一个还是少一个？）
3. **只有一个元素**时会怎样？（删头 = 删尾？链表自环？）
4. **失败的时候**会怎样？（`malloc` 返回 NULL、`realloc` 失败、下标非法）

## 三、指针与内存

### 3.1 动态数组的初始化与扩容

```c
// 初始化
array->data = (int *)malloc(sizeof(int) * capacity);
if (array->data == NULL)
{
    array->capacity = 0;
    array->length = 0;
    return;
}
array->capacity = capacity;
array->length = 0;

// 扩容：realloc 的正确写法（三步）
int *new_data = (int *)realloc(array->data, sizeof(int) * new_capacity);
if (new_data == NULL)
{
    return;                 // 旧指针仍有效，不能直接覆盖
}
array->data = new_data;
array->capacity = new_capacity;   // 千万别忘了
```

**易错**：
- `realloc(p, n)` 的 `n` 是**字节数**，元素数要乘 `sizeof(int)`。
- 不能写 `p = realloc(p, ...)`：失败时旧指针丢失，内存泄漏。
- 扩容后必须更新 `capacity`，否则每次插入都会重复扩容。

### 3.2 二级指针：两层的分配与释放

```c
// 分配
g->rows = (int **)malloc(sizeof(int *) * n);   // 第 1 层：指针数组
for (int i = 0; i < n; i++)
    g->rows[i] = (int *)calloc(n, sizeof(int)); // 第 2 层：每行

// 释放（反着来）
for (int i = 0; i < n; i++)
    free(g->rows[i]);
free(g->rows);
free(g);
```

**易错**：
- 只分配第 1 层，`rows[i]` 是垃圾指针 → `rows[i][j]` 段错误。
- `sizeof(int)` 写成指针数组的大小时：`sizeof(int)` 应为 `sizeof(int *)`。
- 用 `while (rows[i])` 判断行数：未初始化的指针不一定为 NULL。

### 3.3 内嵌数组 vs 堆指针

```c
typedef struct Queue {
    int data[MAX];    // 内嵌数组：随结构体一起 malloc/free
} Queue;

free(q->data);   // ❌ 释放的是结构体内部的地址 → abort
free(q);         // ✅ data 跟着结构体一起走
```

### 3.4 链表销毁

```c
void destroy_list(List *list)
{
    Node *current = list->header;
    while (current != NULL)
    {
        Node *next = current->next;   // 先存 next，再释放 current
        free(current);
        current = next;
    }
    list->header = NULL;
    list->length = 0;
}
```

**易错**：只 `free(header)`；`free` 之后还访问 `current->next`（要先保存 next）。

## 四、数组与指针算术

### 4.1 二维数组的退化

| 表达式 | 类型 | `+1` 前进 |
|---|---|---|
| `int arr[5][5]` 的 `arr` | `int (*)[5]` | 20 字节（一行） |
| `arr[0]` | `int *` | 4 字节 |
| `&arr[0][0]` | `int *` | 4 字节 |

`arr` 和 `&arr[0][0]` **地址值相同、类型不同**：

```c
&arr[0][0] + i * 5 + j   // ✅ 等于 &arr[i][j]
(int *)arr + i * 5 + j   // ✅ 等价
arr + i * 5 + j          // ❌ 类型是 int (*)[5]，步长 5 倍，且解引用得到一行
*(*(arr + i) + j)        // ✅ 正确的"指针写法"二维下标
```

### 4.2 二维数组 vs 指针数组

| | `int arr[5][5]` | `int **rows` |
|---|---|---|
| 内存 | 一整块连续（100 字节） | 指针数组 + 5 块独立内存 |
| 行间关系 | 相邻 | 不连续（有 malloc 间隙） |
| `*(rows+i)` | 纯地址计算 | **真的读内存里的一个指针** |
| 能否展平 | ✅ `&arr[0][0]` 起 | ❌ 绝对不行 |

展平只对**连续存放**的二维数组成立。`int **` 展平后会读到行与行之间的间隙，**不崩溃但结果全错**，比段错误更难查。

### 4.3 传二维数组给 `int *` 参数

```c
void f(int *p);
int arr[5][5];

f(arr);            // ⚠️ warning：arr 是 int (*)[5]
f((int *)arr);     // ✅ 但依赖"连续"这个前提
f(&arr[0][0]);     // ✅ 类型本来就是 int*
f(arr[0]);         // ✅ 第一行退化成 int*
```

优先用 `&arr[0][0]`：不靠强制转换，类型正确，编译器还能继续帮你检查。

## 五、线性结构

### 5.1 单链表

```c
// 头插
new_node->next = list->header;
list->header = new_node;
list->length++;

// 任意位置插入（非头）—— 最容易写错的一行
Node *pre_node = get_pre_node(list, index);
new_node->next = pre_node->next;
pre_node->next = new_node;      // ❌ 曾写成 pre_node->next = pre_node（自环）

// 删除（非头）
pre_node->next = del_node->next;
free(del_node);
list->length--;                 // ❌ 曾漏掉
```

**经典 bug**：`pre_node->next = pre_node;` 会让节点自己指向自己。
- 新节点丢失（泄漏）
- 打印时 `while (node != NULL)` 永远结束不了 → 程序卡死

**调试方法**：画图。三个指针 `pre_node / new_node / new_node->next` 各指向哪，在纸上写清楚。

### 5.2 栈（顺序栈）

```c
void push(Stack *s, int element)
{
    if (s->length == s->capacity)          // 不是 >
    {
        size_t new_capacity = s->capacity == 0 ? 1 : s->capacity * 2;
        resize(s, new_capacity);
        if (s->length == s->capacity)      // 扩容失败
            return;
    }
    s->data[s->length++] = element;
}

bool pop(Stack *s, int *element)
{
    if (s->length == 0)
        return false;
    s->length--;                 // 先减，再取
    *element = s->data[s->length];
    return true;
}
```

**易错**：
- `stack->data[stack->length--];` 只是"读一下再丢弃"，真正起作用的是副作用，写法极不清晰。
- 先取再减的话，打印的"栈顶"就变成了弹栈之后的值。
- `capacity == 0` 时 `2 * 0 = 0`，永远扩不出来，要单独处理。

### 5.3 循环队列

```c
// 判满
(rear + 1) % capacity == front    // 牺牲一个格子
// 判空
rear == front
```

- **实际可用容量 = capacity - 1**。要向队列里放 n 个元素，必须开 `n + 1`。
- 满了 `enqueue` 返回 false，**调用方必须检查**，否则元素被静默丢弃，BFS 结果不完整。
- 用固定 `int data[MAX]` 时，图一宽就不够用；动态分配更通用。
- 空队列返回值不要用 0 当哨兵（0 可能是合法数据/顶点编号），用 `bool + 出参`。

## 六、图

### 6.1 两种存储方式

| | 邻接矩阵 `int **arcs` | 邻接表 `Edge **heads` |
|---|---|---|
| 查边 | O(1) | O(度) |
| 空间 | O(V²) | O(V + E) |
| 适用 | 稠密图 | 稀疏图 |
| 遍历 | `arcs[i][j] == 1` | 沿 `heads[i]` 链表走 |

### 6.2 无向边 = 两条半边

```c
// 加边
add_half_edge(g, from, to);
add_half_edge(g, to, from);     // 第二条失败要回滚第一条

// 删边
remove_half_edge(g, from, to);
remove_half_edge(g, to, from);  // 自环时 from == to，依然要删两条
```

**计数**：邻接矩阵统计 1 的个数后 `/ 2`（自环会让计数不准，需单独考虑）；这一步要放在**双重循环结束之后**，不要写进循环里。

### 6.3 BFS / DFS

```c
// BFS：队列 + visited
visited[start] = 1;
enqueue(q, start);
while (!is_empty(q))
{
    int current;
    if (!dequeue(q, &current))
        break;
    for (每个邻居 i)
        if (边存在 && !visited[i])
        {
            visited[i] = 1;
            enqueue(q, i);
        }
}

// DFS：递归 + visited
visited[index] = 1;
for (每个邻居 i)
    if (边存在 && !visited[i])
        DFS(g, visited, i);
```

**必检查**：
- 条件是 `== 1`（有边），不是 `!= 1`。
- **两次遍历之间必须清零 `visited`**，否则第二次只访问起点。
- 队列容量 `>= 顶点数 + 1`（循环队列浪费一格）。
- `enqueue` 的返回值要检查。
- 图不连通时，要外层循环遍历所有未访问顶点。

### 6.4 邻接表的复杂度和边界

- 加边 O(1)（头插）、删边/查边 O(度)、遍历 O(V + E)。
- 边界：顶点编号越界、空图（0 个顶点）、自环、重复边、删不存在的边、重复销毁。

## 七、交换的三种写法

| 写法 | 需要临时变量 | 溢出风险 | 类型限制 | 同地址安全 |
|---|---|---|---|---|
| 临时变量 | 是 | 无 | 任意类型 | ✅ |
| 加减法 | 否 | **有符号溢出（UB）** | 仅整数 | ❌ 会清零 |
| 异或法 | 否 | 无 | 仅整数 | ❌ 会清零 |

### 异或法原理

```c
*a = *a ^ *b;   // a = A ^ B
*b = *a ^ *b;   // b = (A ^ B) ^ B = A
*a = *a ^ *b;   // a = (A ^ B) ^ A = B
```

用到：`x ^ x = 0`，`x ^ 0 = x`。

### 两个坑

1. **别名问题**：`swap(&x, &x)` 时，第一步 `x = x ^ x = 0`，后面全是 0。排序里 `swap(&a[i], &a[j])` 当 `i == j` 就会踩到。
2. **加减法在 `-O2` 下可能失效**：有符号溢出是 UB，编译器有权把 `swap2` 优化成空操作。

**结论**：工程代码永远用临时变量版；异或/加减法的价值在面试和原理理解。

## 八、二分查找的四种区间写法

| 写法 | 初值 | 循环条件 | mid | 收缩 | 结束状态 |
|---|---|---|---|---|---|
| `[lo, hi]` | `lo=0, hi=n-1` | `lo <= hi` | `lo+(hi-lo)/2` | `lo=mid+1`、`hi=mid-1` | `lo == hi+1` |
| `[lo, hi)` | `lo=0, hi=n` | `lo < hi` | `lo+(hi-lo)/2` | `lo=mid+1`、`hi=mid` | `lo == hi` |
| `(lo, hi]` | `lo=-1, hi=n-1` | `lo < hi` | `lo+(hi-lo+1)/2` | `lo=mid`、`hi=mid-1` | `lo == hi` |
| `(lo, hi)` | `lo=-1, hi=n` | `lo+1 < hi` | `lo+(hi-lo)/2` | `lo=mid`、`hi=mid` | `lo+1 == hi` |

### 统一原则：不变量

选一个不变量，例如 `[lo, hi)`：

> 如果 target 存在，它的下标一定在 `[lo, hi)` 里。

然后保证每一行都维护它：
- `arr[mid] < target` → 答案不在 `[lo, mid]` → `lo = mid + 1`
- `arr[mid] > target` → 答案不在 `[mid, hi)` → `hi = mid`
- 相等 → 返回

闭区间端点自己也是候选，排除时要 `±1`；开区间端点只是哨兵，收缩时直接 `= mid`。

### 四个坑

1. **数组必须有序**（前提）。
2. **`mid` 必须在循环里重新算**（曾写在循环外，每轮比较同一位置）。
3. **`(lo + hi) / 2` 会溢出**，写 `lo + (hi - lo) / 2`。
4. **返回 -1 后不能直接当下标**：`arr[-1]` 是越界读。

### 不要"向上取整"配"向下取整"混用

`(lo, hi]` 用 `lo = mid` 收缩，必须配**向上取整** `lo + (hi - lo + 1) / 2`。
否则 `hi = lo + 1` 时 `mid = lo`，`lo = mid` 不前进 → **死循环**。

### lower_bound / upper_bound

```c
// 第一个 >= target
int lo = 0, hi = n;
while (lo < hi)
{
    int mid = lo + (hi - lo) / 2;
    if (arr[mid] < target) lo = mid + 1;
    else                   hi = mid;
}
return lo;          // 循环结束时 lo 就是插入位置

// 第一个 > target 只需把 < 改成 <=
```

## 九、冒泡排序

```c
void bubble(int arr[], int len)
{
    for (int i = 0; i < len - 1; i++)
    {
        bool swapped = false;
        for (int j = 0; j < len - 1 - i; j++)
        {
            if (arr[j] > arr[j + 1])
            {
                swap(&arr[j], &arr[j + 1]);
                swapped = true;
            }
        }
        if (!swapped)
            break;              // 已经有序，提前退出（最好情况 O(n)）
    }
}
```

**易错**：
- 内层边界写成 `len - 1`（少了 `- i`）会多做无用比较，逻辑仍正确但更慢。
- 外层 `len - 1` 写成 `len` 越界。
- 初始化列表里多一个逗号 `{1,2,,3}` → 语法错误，并且**连带**导致下一行 `sizeof` 报"incomplete type"。

## 十、调试工具与排错流程

### 10.1 编译

```bash
cc -Wall -Wextra -g 源文件.c -o 可执行文件
```

- `-Wall -Wextra`：打开全部常用警告。本次对话里一半的 bug 编译器都直接指出过。
- `-g`：保留行号信息，崩溃和泄漏报告才有文件名/行号。

### 10.2 内存泄漏（macOS）

```bash
leaks --atExit -- ./可执行文件
```

- 必须有 `-g`，否则栈回溯没有函数名和行号。
- 局部变量在 `main` 返回后栈上还残留指针时，`leaks` 可能报 0 —— 假阴性。以代码是否 `free` 为准。

### 10.3 崩溃信号

| 退出码 | 信号 | 常见原因 |
|---|---|---|
| 139 | SIGSEGV | 空指针、野指针、越界写 |
| 134 | SIGABRT | double free、free 非堆指针、堆损坏被检测到 |

### 10.4 排错顺序

1. **先看第一条编译错误**，后面的常常是连锁反应。
2. **再看所有 warning**，尤其是 `incompatible pointer types`。
3. 编译通过但崩溃：找 `0x0` 地址 → 空指针；找刚 free 过的指针 → use-after-free。
4. 结果不对但不崩：检查边界（`>` / `>=` / `==`）、`length/capacity` 是否同步、`visited` 是否清零。
5. 最后跑 `leaks` 查遗漏的 `free`。

## 十二、自测清单

写任何数据结构前，用这份清单过一遍：

### 初始化

- [ ] 所有成员都在使用前赋了值？
- [ ] `malloc/calloc` 的返回值判了 NULL？
- [ ] 二级指针的两层都分配了？`sizeof` 用的是指针类型吗？
- [ ] 函数有返回值类型时，每条路径都有 `return`？

### 操作

- [ ] 空的时候（`length == 0`）会怎样？
- [ ] 满的时候（`length == capacity`）会怎样？
- [ ] 只有一个元素时，插入/删除/取前驱还对吗？
- [ ] 下标检查是 `>` 还是 `>=`？
- [ ] 修改数据后，`length` / `capacity` / `count` 同步了吗？
- [ ] 指针赋值时，两个指针是不是指反了？（`a->next = b` 还是 `b->next = a`）

### 释放

- [ ] 每个 `malloc` 都有对应的 `free`？
- [ ] 释放顺序是从内到外吗？
- [ ] `free` 的是堆指针，不是内嵌数组/栈地址？
- [ ] 释放后有没有把指针置 NULL？
- [ ] 有没有在释放后继续使用？

### 遍历

- [ ] 两次遍历之间，`visited` 清零了吗？
- [ ] 队列/栈容量够不够（循环队列要 +1）？
- [ ] `enqueue`/`push` 失败检查了吗？
- [ ] 遍历能终止吗？（链表有没有自环、指针有没有不前进）

### 编译器

- [ ] 用 `-Wall -Wextra` 编译过？
- [ ] 所有 warning 都看过并确认无害？
- [ ] 跑过 `leaks --atExit -- ./程序`？
